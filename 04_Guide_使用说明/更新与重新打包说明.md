# 更新与重新打包说明

## 更新原则

每次业务或页面修改都应保持以下内容同步：

1. `03_Deliverable_最终作品/项目源码` 中的本地源码。
2. 公开线上站点。
3. `版本说明.md` 中的版本日期、变更内容和验证结果。
4. 面向外部交付的 ZIP 压缩包。

## 推荐流程

1. 修改源码和必要的中文交付说明。
2. 执行 `npm run export:html`，同步生成三份本地 HTML。
3. 执行 `npm run lint` 和 `npm test`。
4. 将通过验证的同一源码版本发布到线上。
5. 更新版本说明。
6. 重新生成交付包，排除 `node_modules`、`dist`、`.git`、缓存和临时文件。
7. 检查压缩包能否正常解压，并确认本地 HTML、作品入口及在线链接正确。

## 不应放入交付包的内容

- 账号凭证、访问令牌和本地环境变量。
- `node_modules`。
- `.git` 历史目录。
- 构建缓存和临时调试文件。
- 已过期的旧压缩包。
